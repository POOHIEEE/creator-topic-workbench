# Creator Topic Workbench · 竞品选题工作台

**别只收藏同行的内容，把它变成自己下一条能拍的选题。**

一个作者优先、证据可追溯的 Agent Skill，附零依赖离线看板生成器。适合内容创作者、AI博主和做实践分享的产品经理。

> 当前版本：v0.2.0。这是从实际工作流程中提炼的可复用 Skill 与生成器，不是个人线上工作版的完整源码备份。仅分发工具代码、说明和虚构教学样例，不包含私人看板、账号研究数据或录屏。

## 为什么做这个

刷了很多同行、收藏了很多爆款，最后仍不知道自己下一条拍什么。问题往往不是信息太少，而是没有回答：**这个作者为什么这么切题？哪一部分值得学？换成我的受众和案例，还成立吗？**

这个项目把这条判断过程固定下来：原作和数据不丢，借鉴依据说清楚，最后交付自己的选题和制作前检查项。目标不是复制同行，而是减少从“看到参考”到“知道怎么做”的距离。

## 它帮你做什么

作者是谁 → 最近做了什么 → 数据是否可比 → 借鉴哪一部分 → 换成自己的案例 → 形成脚本与镜头计划。

不是让你对着一堆链接自己写。Skill指导Agent解释转化理由，生成面向观众、简短口语化的标题，并写清需要验证的部分。

| 能力 | 当前边界 |
| --- | --- |
| 作者维度的原作和选题总览 | 支持导入结构化证据；不是全网实时搜索引擎 |
| AIGC / 通用选题分开 | 不把所有题目混进一个榜单 |
| 原作、时间、指标可追溯 | 缺失指标显示未知，不编造播放或收藏 |
| 转成自己的标题、案例和制作步骤 | 由Agent结合上下文整理，不是本地脚本自动调用大模型 |
| 可运行离线看板 | 生成HTML和QA；没有内置爬虫、定时器、账号托管或发布功能 |

## 最快试一次

需要 Node.js 20+。不需要安装依赖或配置API Key。

```bash
git clone https://github.com/POOHIEEE/creator-topic-workbench.git
cd creator-topic-workbench
node scripts/workbench.mjs examples/evidence.json out
node scripts/export-briefs.mjs examples/evidence.json out/briefs
node --test
```

打开 `out/index.html`。示例全部标注为虚构教学数据，不能用来论证任何作者表现。

以上命令只是生成本地演示，不采集平台数据、不调用模型、不部署网站。首次使用可先让 Agent 读取本仓库的 `SKILL.md`，再提供你的内容方向及参考作者；网络检索依赖 Agent 已有的工具与合法访问权限。

输出文件：

| 文件 | 用途 |
| --- | --- |
| `out/index.html` | 作者原作、证据和AIGC/通用选题；展开标题查看转化依据与验证步骤 |
| `out/qa.json` | 输入数据的校验结果、缺失日期和过期证据提醒；不是内容质量评测 |
| `out/briefs/index.md` | 按AIGC/通用分类的制作卡索引 |
| `out/briefs/topic-01.md`等 | 保留作者、原作、自己的案例和验证步骤的Markdown制作卡 |

完整操作与真实资料接入见 [使用指南](USAGE.md)。

接真实资料时，把作者、原作、日期、已观察到的指标填入同样的JSON，再让Agent按 `SKILL.md` 填写选题的转化理由和验证步骤。数据字段见 [证据契约](references/evidence-contract.md)。

## 作为Skill使用

将本目录放入支持Agent Skills的工具的技能目录，确保 `SKILL.md` 可发现。例如Codex使用 `~/.codex/skills/creator-topic-workbench/`。安装不意味着已获得任何平台的登录态或采集权限。

可以这样问：

> 根据这些作者原作，找出适合我做的内容。先给作者和证据，再给我的标题、借鉴点、自己的案例、待验证项。AIGC和通用分开，不只改写原标题。

## 一条选题应包含什么

| 字段 | 要回答的问题 |
| --- | --- |
| 参考原作 | 借鉴的是谁、哪一篇？ |
| 观众问题 | 他为什么要看？ |
| 借鉴点 | 学的是表达、工作流还是结果？ |
| 自己的案例 | 不是搬运，我拿什么来证明？ |
| 验证步骤 | 拍之前还缺什么？ |

### 看一个转化例子

以下是虚构教学案例，不代表真实作者或项目能力：

| 环节 | 示例 |
| --- | --- |
| 参考内容 | 某作者介绍“AI做视频全流程” |
| 观众的实际问题 | AI说剪好了，但字幕、声音或者文件可能还有错 |
| 借鉴点 | 用最终交付证明能力，而不是念功能清单 |
| 我的选题草案 | **AI剪的视频，我检查了一遍** |
| 我自己的案例 | 用自有短片检查播放、字幕和音轨，展示实际错误与修复 |
| 发布前要验证 | 有没有真实失败样本？修复是否有效？画面与说法是否对应？ |

标题是待验证草案。只有真的做过、能拿出画面，才可以用第一人称描述结果。

## 与普通信息汇总有什么区别

- **先作者，后结论**：知道借鉴谁，不是只看到抽象“爆款公式”。
- **来源留在结果旁边**：原作、发布与采样时间、证据深度一起保留。
- **数据不是装饰**：播放、赞、收藏分开；缺失不冒充零，旧数据不冒充今日刷新。
- **最后要有自己的题**：受众、标题、案例、验证步骤都写清，不让用户面对空白继续加工。
- **工具边界透明**：Skill指导研究与判断，脚本负责校验与展示；没有隐藏的全网采集或自动发布服务。

## 设计参考

参考 [social-media-research-skills](https://github.com/ScrapeCreators/social-media-research-skills) 的来源引用与作者内基线意识，以及 [huashu-report](https://github.com/alchaincyf/huashu-report) 的成果交付思路。本项目代码与说明独立编写，未复制第三方Skill正文或媒体资产。外部采集服务可能收费，本地看板生成器不依赖它们。

## 不承诺什么

- 不保证爆款、涨粉或内容效果。
- 不绕过登录、验证码、平台限制，不抓私密内容。
- 不把累计播放直接当质量，不把作者宣称写成亲测。
- 没有内置实时数据或自动运营；定期监控需要单独配置数据入口与调度器。
- 仓库不包含任何个人工作版的私有地址、账号历史、凭据或转载视频。

## 测试与隐私

当前10项自动测试覆盖：示例可生成、AIGC/通用分组、未知值与真实零区分、原作关联、旧证据提醒、危险URL拒绝、HTML转义和错误输入，以及制作卡来源保留、受控文件名和错误引用拒绝。

`out/`、`.env`、`private/` 与 `local-memory.md` 默认忽略，但忽略规则不是脱敏工具。接真实资料后，请在每次提交前检查文件清单，不上传登录凭据、私密内容、未经许可的媒体或个人工作版记忆。生成的HTML直接包含输入内容，也需要按资料的隐私等级保存和分享。
